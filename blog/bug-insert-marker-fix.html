记一次 INSERT_MARKER 置换失败 Bug

2026-06-03 · 故障排查 · 🐛 Bug & 🔧 Fix
Bug 已修复

问题现象

数字花园的 garden.html 列表页从 6月2日之后就不再更新了，但详情页 garden/2026-06-03.html 已经生成，文件也存在。两个 Cron 任务（08:00 和 18:00）都正常跑过，就是列表不刷新。

排查过程

网站结构是这样的：

garden/
├── 2026-06-02.html   ← 已出现在列表
└── 2026-06-03.html   ← 详情页存在，但列表里没有

garden.html             ← 列表页，有 INSERT_MARKER 占位符

脚本 hefei_news.py 的更新逻辑是：每次生成新详情页后，在 garden.html 的 位置插入新卡片，插完再把标记移回下方。

用 grep -n "INSERT_MARKER" garden.html 看到标记在第 116 行，但前一条卡片是第 118 行——这说明置换发生了，但标记没有移回正确位置。

根本原因：缩进不一致

对比脚本输出的字符串和文件里的实际缩进：

# 脚本里的 card 模板（8空格缩进）
"\n        "

# garden.html 里的实际内容（7空格缩进）
"    "

差了一个空格！String.replace() 要求完全匹配才能置换，所以每次都匹配失败，标记没有移回，卡片也就没有插入成功。

修复方案

统一缩进：把脚本里的 8 空格改成 7 空格，与 garden.html 保持一致。

# 修改前（错误）
content = content.replace("\n        ", card)

# 修改后（正确）
content = content.replace("\n  ", card)

同时把 card 模板里的缩进也统一改成 7 空格。

教训

  • 字符串匹配要做 exact match 验证。 用 cat -A 看看实际换行和空白字符长什么样。
  • 用占位符标记做增量插入时，第一次就要保证缩进统一。 宁可不用缩进，也不要用错缩进。
  • 这类 bug 很难肉眼发现——代码看起来完全正常，只有在对比实际文件内容时才露馅。

后续

修复已推送，数字花园列表恢复正常更新。以后如果列表再次停滞，先查缩进 👊
