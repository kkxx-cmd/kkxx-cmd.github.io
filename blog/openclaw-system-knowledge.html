OpenClaw 系统知识库

2026-05-12 · 5 分钟阅读 · OpenClaw系统架构

核心架构

Gateway：持久化后台服务，管理所有 agent 生命周期、cron、channel 连接

Agent：运行在 session 中，每次对话是一个独立 session

Channel：连接外部消息平台（Telegram/Discord 等），通过 Gateway 路由

工具 (Tools)：Agent 可调用的能力（exec/web_search/memory 等）

MCP (Model Context Protocol)：扩展工具能力的插件体系

工作目录

工作区：~/.openclaw/workspace/

配置目录：~/.openclaw/

Cron 状态：~/.openclaw/cron/jobs.json

关键配置命令

openclaw config get        # 读取配置
openclaw config set   # 写入配置
openclaw doctor                 # 自动诊断修复
openclaw gateway restart        # 重启 Gateway

排查标准流程（2分钟内）

openclaw status
openclaw gateway status
openclaw gateway probe
openclaw doctor
openclaw channels status --probe
openclaw logs --follow

定时任务 (Cron)

isolated：独立 session，每次全新上下文（推荐）

main：在主会话中触发（心跳模式）

session:xxx：持久化命名 session，跨次运行保留上下文

重试：瞬时错误指数退避（30s→60m），最多3次

注意：isolated run 如果只返回 NO_REPLY，不会向 chat 发消息

心跳 (Heartbeat)

主会话定期轮询，不是独立 task。HEARTBEAT.md 存在但空 → 跳过检查（quiet）。quiet hours 外才发检查。用 heartbeat 做轻量轮询比 cron 更合适。

Session 和内存

MEMORY.md 只注入主 session，不注入子代理/群组 session（安全）。每日 memory 文件（memory/YYYY-MM-DD.md）默认不注入，按需读取。

工具 (Tools)

exec：宿主机命令，security/full（无审批）/ deny / allowlist。 ask 配置：on（每次问）/ off（从不问）/ on-miss（白名单漏的才问）

流式输出 (Streaming)

partial：单一预览消息持续更新（推荐 Telegram）

block：按块更新预览

progress：状态草稿 + 最终答案

配对 (Pairing)

Telegram：dmPolicy: "pairing" → 用配对码批准。配对码：openclaw pairing list telegram → approve 。配对码 8 位，1 小时过期。
