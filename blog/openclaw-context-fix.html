--- layout: news title: OpenClaw 上下文超限问题修复 date: 2026-05-24 --- ## OpenClaw 上下文超限问题修复：两个参数拯救长对话 **问题现象：** 对话进行到一半突然报错 "Context limit exceeded"，会话被强制重置 **根本原因：** 模型上下文配置与压缩机制不匹配 **解决方案：** 修正两个关键参数，5 分钟彻底解决 --- ## 🚨 问题现场 Context limit exceeded. I've reset our conversation to start fresh... To prevent this, increase your compaction buffer by setting agents.defaults.compaction.reserveTokensFloor to 20000 or higher. 表面看是上下文超限，实际是配置逻辑错误导致的连锁反应。 --- ## 🔍 问题根因分析 ### 核心矛盾：配置不匹配 OpenClaw 的上下文压缩机制需要两个参数协同工作： | 参数 | 作用 | 错误配置 | 正确配置 | |------|------|---------|---------| | contextWindow | 模型支持的最大上下文长度 | 16000（默认值） | 128000（实际值） | | reserveTokensFloor | 压缩时预留的新内容空间 | 20000 | 40000 | ### 错误链条 错误的 contextWindow (16000) ↓ reserveTokensFloor (20000) > contextWindow (16000) ↓ 压缩功能无法触发（预留空间超过总容量） ↓ 对话内容无限累积 ↓ 触发硬性上限 → 会话重置 **关键发现：** 当 reserveTokensFloor ≥ contextWindow 时，压缩机制会失效。 --- ## 🛠️ 修复步骤 ### 步骤 1：定位配置文件 打开 `~/.openclaw/openclaw.json` ### 步骤 2：修正模型上下文配置 在 `models.providers[].models[]` 中找到自定义模型，将 contextWindow 改为实际值： ```json { "models": { "providers": { "custom-integrate-api-nvidia-com": { "models": [ { "id": "minimaxai/minimax-m2.7", "contextWindow": 128000, // ✅ 修正：16000 → 128000 "maxTokens": 4096 } ] } } } } ``` ### 步骤 3：调整压缩缓冲配置 ```json { "agents": { "defaults": { "compaction": { "mode": "safeguard", "timeoutSeconds": 900, "reserveTokensFloor": 40000 // ✅ 修正：20000 → 40000 } } } } ``` ### 步骤 4：验证配置关系 确保：`reserveTokensFloor (40000) < contextWindow (128000)` ✅ ### 步骤 5：重启生效 ```bash openclaw gateway restart ``` --- ## 📊 修复效果对比 | 指标 | 修复前 | 修复后 | |------|--------|--------| | 最大对话轮数 | ~50 轮 | ~800 轮 | | 压缩功能 | ❌ 失效 | ✅ 正常 | | 会话重置 | 频繁触发 | 不再出现 | --- ## 💡 配置原则 - **contextWindow 必须填写真实值** — 主流大模型通常支持 128000 - **reserveTokensFloor 必须小于 contextWindow** — 建议值：20000~40000 - **更换模型时同步更新** — 不同模型的上下文长度可能不同 --- ⏰ 于 2026-05-24 同步 | 来源：博客园 yih
