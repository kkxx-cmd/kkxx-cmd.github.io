OpenClaw Dreaming 睡眠记忆系统

OpenClaw 内置了一个后台记忆整合系统，称为 Dreaming（睡眠记忆）。它在模型空闲时自动运行，将短期记忆信号提炼为长期记忆，同时保持整个过程可追溯、可审查。

核心机制

Dreaming 通过三个协作阶段完成记忆整理：

阶段作用写入 MEMORY.md
------------:---:
Light（浅睡）读取并去重短期记忆信号，为深度候选做准备❌
Deep（深睡）评分候选内容，满足阈值后写入长期记忆✅
REM提取主题和模式，识别重复出现的想法❌

关键原则：只有 Deep 阶段会将内容写入 MEMORY.md，其余阶段只做分析。

具体做什么

Light 阶段：

  • 从短期召回状态、每日记忆文件、会话记录中读取近期信号
  • 去重并整理候选条目
  • 从不直接写入 `MEMORY.md`

Deep 阶段：

  • 根据加权评分对候选内容排名
  • 需同时满足三项阈值：`minScore`（分数）、`minRecallCount`（召回次数）、`minUniqueQueries`（独立查询数）
  • 满足条件的内容追加到 `MEMORY.md`

REM 阶段：

  • 分析近期短期记忆痕迹，建立主题和反思摘要
  • 不直接写入 `MEMORY.md`，为 Deep 阶段提供信号

深度排名信号

Deep 阶段使用六个加权信号综合评分：

信号权重说明
------------------
Frequency（频率）0.24条目累积的短期信号数量
Relevance（相关性）0.30平均检索质量
Query diversity（查询多样性）0.15触发条目的独立查询/天数
Recency（时效性）0.15时间衰减后的新鲜度
Consolidation（巩固度）0.10多日 recurrence 强度
Conceptual richness（概念密度）0.06概念标签密度

Dream Diary

Dreaming 还维护一份人类可读的 Dream Diary（梦境日记），记录在 DREAMS.md 中。每次完整运行后会追加一段简短的日记条目，供人工回顾。

日记内容仅供审查，不会被自动提升为长期记忆。

输出文件

Dreaming 写入两类数据：

  • **机器状态**：`memory/.dreams/` 目录（recall store、phase signals、ingestion 检查点）
  • **人类可读**：`DREAMS.md`（梦境日记）+ 可选的 `memory/dreaming//YYYY-MM-DD.md` 分阶段报告

默认行为

配置项默认值
----------------
启用状态**默认关闭**（opt-in）
运行时间每天 03:00
使用模型默认 runtime 模型

启用方式

在 openclaw.json 中添加：

{

"plugins": {

"entries": {

"memory-core": {

"config": {

"dreaming": {

"enabled": true

}

}

}

}

}

}

自定义运行频率（示例：每6小时一次）：

{

"plugins": {

"entries": {

"memory-core": {

"config": {

"dreaming": {

"enabled": true,

"frequency": "0 */6 * * *"

}

}

}

}

}

}

CLI 命令

查看状态

openclaw memory status --deep

手动触发记忆提升预览/应用

openclaw memory promote

openclaw memory promote --apply

openclaw memory promote --limit 5

解释为何某条内容未提升

openclaw memory promote-explain "关键词"

预览 REM 阶段输出（不写入）

openclaw memory rem-harness

/dreaming 命令

/dreaming status # 查看当前状态

/dreaming on # 启用

/dreaming off # 禁用

/dreaming help # 帮助

状态显示 blocked

如果 openclaw memory status 显示 Dreaming status: blocked，说明管理的 cron 存在但默认 agent 的心跳未触发。检查心跳是否启用，以及目标是否设置为 none。
